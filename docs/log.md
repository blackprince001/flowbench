# Log

## 2026-07-20

- **Extract / assert / template chaining (issue #5, ADR 0011).** The chaining primitive that makes a flow more than a list of calls: extract values from one response into flow variables, inject them into later requests, assert on the result. Two new packages. `internal/eval` is adapter-neutral and dependency-free: a hand-rolled JSONPath subset (`$.a.b`, `$['a.b']`, `$.a[0]`, negative indices; filters/wildcards/recursive-descent rejected at parse time — ADR 0011), assertion evaluation across all five sources (status, latency, header, body, var) and ten ops (eq/ne/lt/lte/gt/gte/contains/matches/exists/not_exists) with numeric coercion and duration-aware latency compares, and extraction over a small `Target` interface so M3's GraphQL/gRPC adapters reuse it. `internal/executor` gains `Scope` (env / bound data-pool row / extracted vars, with the templating resolver injection uses) and a single-iteration `Runner` that chains a flow's call and wait steps: build request → adapter `Do` → extract (populating scope) → assert, emitting one child span per extraction and assertion under the step span. Failure handling honors `on_failure` with the PRD section 12 mode-aware default (loud/abort_flow in integration/system, recorded data in load/stress/soak); a failure is always recorded in the iteration regardless, and `abort_run` flags the whole run to stop. The M2 goroutine-per-VU pool will drive many of these concurrently. Acceptance green: the PRD section 11 chained checkout (login → extract token → authenticated order → extract id → pay → assert 202) runs end to end against a stub; a failing assertion is recorded per iteration; the integration default stops the flow at the first failure.

## 2026-07-12

- **YAML DSL parser (issue #3, ADR 0010).** `internal/parser` turns one `*.flow.yaml` into a validated single-flow scenario on `goccy/go-yaml` (ADR 0010: actively maintained where `gopkg.in/yaml.v3` is frozen legacy; AST tokens carry line/column — the project's first dependency, confined to the parser package). The walker maps the AST to IR filling `Pos` on flows and steps, so schema errors get exact `file:line:col` and IR validation errors (including variable-graph failures) get the step's `file:line`; all problems report together, compiler-style. DSL v0 surface: `call: METHOD url` shorthand with headers/query/body, `wait`, `poll` blocks, `extract` (JSONPath), the assertion expression grammar (`status == 200`, `token != null` → exists, `latency < 800ms`, `$.path`, `header.Name`, contains/matches), `retry`, and both profile `vus` forms; `data:` binds fixture rows as `{{ user.* }}` (matching the PRD sample; a named-pool form stays additive); missing profile defaults to integration mode. The step-rename warning hook (PRD 10.7) is in: `Options.PriorStepIDs` → warnings when a prior structural name disappears, ready for the run store to feed. Acceptance green: the PRD section 11 sample parses to IR; an undefined `{{ var }}` fails with file/line.
- **M1 started: engine skeleton and IR v0 (issues #1, #2).** First code on branch `feat/m1-bootstrap-and-ir`. Go module `github.com/blackprince001/flowbench` with the PRD section 13 package layout (parser, planner, executor, adapters, collector, store — doc.go responsibility statements only, no stub code), `flowbench version` via a stampable `internal/version`, and the conventional `tests/` layout as a worked example carrying the PRD's `authenticated_checkout` sample. `internal/ir` defines the canonical flow representation: Step as a discriminated union over `call/logic/wait/poll/verify` with open string enums (so `ws` and a possible `prompt` kind stay additive per the issue #2 scope note — no model/params fields, per ADR 0009's observe-don't-own), per-step capture flags, span-safe identifiers (`.` and `@` reserved for `login.http_call.tls` dot-paths and `name@variant`), strict JSON decoding, and validation that resolves the variable graph (env / bound data pool / upstream extraction; same-step vars visible to assertions but not injection). Ramp, arrival-cap, and threshold expressions ride verbatim as strings per the PRD ERD until the planner owns them (M2). Acceptance green: `go build ./...`, `go test ./...`, chained-login fixture validates, round-trip locked by a golden file.
- **Revision: observe, don't own (PRD v0.5 → v0.6, ADR 0009 rewritten).** Course-corrected the prompt-testing design after review: FlowBench must not make LLM calls, template prompts, or set model behavior — teams already have SDKs and frameworks for that. Dropped the `prompt` step type and LLM provider adapter; replaced with a **prompt-observation API** on the Python SDK (`ctx.prompt(...)` … `p.record(...)`) that wraps the flow's own SDK call inside a `logic` step: always-on prompt/completion capture, identity hashing (author-supplied `template=` or recorded content), variants as labels (`name@variant` span identity), and **pace/timeout guards** (client-side rate ceiling coordinated across VUs/workers) so calls repeated N times don't get rate limited. Diff view unchanged. GitHub issues #43/#44 rewritten, #45 retargeted; M3 milestone description updated.
- **Scope: AI prompt testing (PRD v0.4 → v0.5, ADR 0009).** Added prompt testing to v1 scope as diff-first prompt interactions in the existing flow model: completions chain like any extraction; prompt + completion always captured (carve-out from the failures-plus-sample capture policy); prompt-identity hashing; named variants with per-variant span identity; and a results-server prompt diff view (variant vs variant, run vs baseline; text and structural JSON diffs). Explicit non-goals: LLM-as-judge, semantic-similarity scoring, eval datasets, prompt registries. New PRD section 10.9; observation work lands in M3, diff view in M4 — mirrored in GitHub milestone descriptions and new tracer-bullet issues.
